# pitwu-web セットアップの注意点

最終更新: 2026-10-13

基本の手順は [`setup.md`](setup.md) のとおり。ここでは、実際にセットアップしてつまずいた点と、守ったほうがよい点を、作業者側と Claude（Claude Code）側に分けてまとめる。

## 作業者側の注意ポイント

人が自分でやる必要があることと、判断が必要なこと。上から順に確認すればよい。

**事前準備**

- [ ] 管理者から GitHub の Collaborator 招待を受け、**招待を承認する**（承認するまでは push が 403 で拒否される）
- [ ] microCMS のサービスドメインと GET 権限のみの API キーを、共有保管庫など安全な方法で受け取る
- [ ] Node.js が 22.12 以上であることを確認する
- [ ] GitHub CLI を入れる（`winget install --id GitHub.cli -e` → VSCode を再起動 → `gh auth login`）。ログインはブラウザ操作があるので自分で行う

**キーの扱い**

- [ ] `.env` は VSCode で開いて自分で書き込む。`=` の後ろに値だけを書き、引用符や空白は入れない
- [ ] API キーを Claude のチャットや Slack に貼らない
- [ ] `.env` をコミットしない（`.gitignore` 済みだが念のため）

**Windows の制約**

- [ ] スマート アプリ コントロールがオンの PC では biome.exe がブロックされ、`npm run lint` が動かない。lint は GitHub Actions に任せる
- [ ] そのためにスマート アプリ コントロールをオフにしない（PC 全体の保護が弱まり、元に戻せない場合がある）

**ローカルでの確認**

- [ ] `npm run dev` では、スケジュールの予定表示・問い合わせの送信・検索は動かない。これは正常な動作
- [ ] キーが空だと、サーバーは起動しても全ページが 500 エラーになる

**PR とマージ**

- [ ] PR の宛先（base）が `staging` になっているか確認してからマージする。push 時に表示される PR 作成リンクは宛先が `main`（本番）になっている
- [ ] PR のマージは自分で行う。Claude Code は自分で作った PR をマージできない（安全機能で止められる）
- [ ] ステージングはまだアクセス制限（Cloudflare Access）が未設定。外に出せない内容を載せない
- [ ] ステージングで問い合わせフォームが送信エラーになるのは正常（本番の事務局に届かないようにしてある）

**後片付け**

- [ ] テスト用の変更を `staging` に入れたら、確認後に必ず取り消す。残すと次の `staging` → `main` で本番に出てしまう
- [ ] 使い終わった作業ブランチは GitHub 上でも削除する
- [ ] リモートの `main` が強制 push で書き換わったときは、未コミット・未 push の作業がないことを確かめてからクローンし直す

## Claude 側の注意ポイント

Claude Code に作業させるときに守らせること。今回実際に起きた失敗や、起きかけたことをもとにしている。作業の最初にこの表を Claude に渡すとよい。

| 守らせること | 理由 |
| --- | --- |
| VSCode では `pitwu-web` フォルダそのものを開いて作業させる | リポジトリの CLAUDE.md（ブランチ運用・公開リポジトリの注意など）を Claude が自動で読むようにするため。親フォルダで開くと、別のプロジェクト用の指示が読まれることがある |
| 開発サーバーを止めてから `npm ci` を実行させる。依存関係に変更がなければそもそも実行させない | 起動中に実行するとファイルのロックで失敗し、node\_modules が壊れる（今回実際に起きた） |
| 作業ブランチは `origin/staging` から作り、追跡先（upstream）を `staging` のままにしない。push はブランチ名を明示させる | `git switch -c … origin/staging` は追跡先が `staging` になるため、設定次第では `staging` に直接 push してしまう |
| PR は `--base staging` を指定して作らせる | `gh pr create` の既定の宛先は `main`（本番） |
| PR のマージは人が行う。Claude には作成までを任せる | Claude Code の安全機能で、自分で作った PR のマージは止められる。人が中身と宛先を確かめる機会にもなる |
| `.env` の中身は、値を伏せた形でだけ確認させる（「値あり」「空」など） | キーが会話のログに残らないようにするため |
| フォルダやブランチを削除する前に、未コミットの変更・未 push のコミット・`.env` の中身を確認させる | 消すと元に戻せない。特に `.env` は git の管理外なので、クローンし直しても戻らない |
| lint が動かないときに、セキュリティ設定を回避させない | スマート アプリ コントロールによるブロックは仕様。lint の結果は Actions で確認させる |
| インストール直後の gh が見つからないときは、フルパス（`C:\Program Files\GitHub CLI\gh.exe`）で実行させる | VSCode を再起動するまで PATH が更新されない |
| テスト用の変更は、取り消しまでを一連の作業として扱わせる | 取り消し忘れると、次の `staging` → `main` で本番に出てしまう |
